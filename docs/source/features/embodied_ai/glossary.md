## 单一事实源（SSOT）

**定义：**  
`robot_config` 中的一种设计原则：由单个 YAML 配置文件定义完整的机器人硬件、外设、控制器与 ML 契约。这避免了配置源重复，并提供规范化、可合并的机器人设置。

**实现与数据流：**

- `robot_config` 包加载这些 YAML 文件，统一 `ros2_control` 硬件、相机驱动（usb_cam 或 realsense2_camera）与面向 ML 推理的 tensor message 契约。
- YAML 一并定义关节、控制器、外设与推理流水线。
- 通过 `base_config` 的 overlay 与继承机制支持无重复的扩展。
- 校验与合并逻辑保证类型安全且继承无环（[src/robot_config/robot_config/loader.py:90-133](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/robot_config/robot_config/loader.py#L90-L133)、[src/robot_config/README.md:5-145](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/robot_config/README.md#L5-L145)、[src/robot_config/config/robots/so101_single_arm.yaml:5-195](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/robot_config/config/robots/so101_single_arm.yaml#L5-L195)）。

## 控制模式（Control Mode）

**定义：**  
预定义的机器人运行模式，决定控制接口与推理行为。例如 `teleop`、`model_inference` 和 `moveit_planning`。

**实现：**

- 在机器人 YAML 的 `control_modes` 下配置，含控制器列表、推理开关与执行器类型/模式。
- launch 文件据此启动相应控制器与节点：如 `model_inference` 启用推理流水线，`moveit_planning` 启动 MoveIt 轨迹服务器（[src/robot_config/config/robots/so101_single_arm.yaml:50-120](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/robot_config/config/robots/so101_single_arm.yaml#L50-L120)、[src/robot_config/launch/robot.launch.py:1-136](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/robot_config/launch/robot.launch.py#L1-L136)）。

## 流水线（Pipeline，推理流水线）

**定义：**  
表示推理服务中模型执行流水线的逻辑标识符。每个流水线拥有模型 bundle、部署目标、前/后处理器、运行时句柄与通信端点。

**实现与数据流：**

- 在机器人 YAML 的 `control_modes.<mode>.inference.pipelines` 下定义，含模型路径、部署与执行模式。
- 推理服务（`inference_service`）按流水线从 `inference_manifest.json` 加载 bundle 与 deployment。
- `InferencePipeline` 门面管理运行时句柄、生命周期、准入控制与诊断（[src/inference_service/README.md:1-200](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/inference_service/README.md#L1-L200)、[src/robot_config/config/robots/so101_single_arm.yaml:75-105](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/robot_config/config/robots/so101_single_arm.yaml#L75-L105)）。

## Bundle

**定义：**  
自包含的文件目录，代表可部署的 AI 模型，包括配置、权重、tokenizer、前/后处理器与 `inference_manifest.json`。

**实现：**

- 要求 manifest v3 格式，列出全部文件、文件摘要与 deployment。
- 可包含面向不同后端目标（Torch、RKNN、OM、HMM）的多个 artifact。
- 由 `inference_service` 与 `robot_config` 用于模型加载与运行时选择（[src/inference_service/README.md:37-60](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/inference_service/README.md#L37-L60)、[src/inference_manifest/README.md](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/inference_manifest/README.md)）。

## Deployment

**定义：**  
bundle 内命名的运行时 profile，指定后端类型、硬件目标、设备细节与 artifact 引用。

**实现：**

- 在 `inference_manifest.json` 中声明，含 UUID、修订版本、运行时 profile、执行契约与 artifact 路径。
- deployment 名称（如 `cpu`、`rk3588`）用于流水线选择与运行时实例化。
- 支持多目标模型分发与硬件特定优化（[src/inference_service/README.md:62-152](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/inference_service/README.md#L62-L152)）。

## Manifest v3

**定义：**  
`inference_manifest.json` 的第 3 版 JSON schema，定义 bundle 结构、文件、deployment、执行顺序与 ABI 绑定。

**实现：**

- 作为运行时加载与完整性校验的权威来源。
- 描述 bundle、含运行时 profile 与 artifact 的 deployment、执行阶段与张量绑定。

## DispatchBinding

**定义：**  
Protocol Buffer/ROS 2 消息，表示分布式任务分发与技能调用中委托执行的绑定根标识符。

**实现：**

- 在 `ibrobot_msgs/msg/DispatchBinding.msg` 中定义为 ROS 消息类型。
- 随委托动作（`PickObject`、`PlaceObject`）传递，用于关联 goal 请求与技能注册身份及任务预算。
- 确保分布式或委托执行的准入控制与跟踪一致（[src/ibrobot_msgs/msg/DispatchBinding.msg](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/ibrobot_msgs/msg/DispatchBinding.msg)、[src/manipulation_execution/README.md:74-80](https://atomgit.com/openeuler/IB_Robot/blob/openEuler-26.09/src/manipulation_execution/README.md#L74-L80)）。

## AutoHorizon

**定义：**  
动态控制特性或参数，在模型推理或分发调度中启用自适应视界（horizon），平衡延迟与预测窗口长度。

**实现：**

- 该参数或概念隐式存在于 `action_dispatch` 与推理调度层，但文档化为平衡动作块（chunk）长度与延迟的调优旋钮。
- 在推理与分发系统的调度配置中管理。

## Temporal Ensemble（时间集成）

**定义：**  
跨多个相邻推理结果的时间平滑或集成技术，提升预测随时间的稳定性。

## OM / ATC / CANN

**定义：**

## 说明

- 所有机器人配置位于 `src/robot_config/config/robots/` 下的 YAML 文件，`so101_single_arm.yaml` 是规范示例。
- 机器人 launch 流程（`robot.launch.py`）基于配置与控制模式动态加载硬件、控制器、感知服务、moveit、遥操作与推理流水线。
- 推理 bundle 使用模块化且可扩展的 manifest v3 schema，对在异构后端上运行模型至关重要。
- `DispatchBinding` 与 `TaskBudget` 消息表示分布式技能编排所需的委托动作元数据。
- 嵌入式具身 agent（`Hermes`）管理高层 AI 驱动的任务执行，依赖技能目录与能力网关。
- OM、ATC、CANN（昇腾）、RKNN（Rockchip）、HMM（华为）等平台特定术语表示通过构建与部署工具标准化的模型部署格式与工具链。
